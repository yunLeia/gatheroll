# 모두가 보는 이벤트 앨범

- 문제: 업로드는 가능했지만 호스트와 다른 참가자가 결과물을 볼 수 없었다.
  사용자가 원하는 것은 승인된 모든 참가자가 함께 보는 앨범이다.
- 원리: `apps/api/src/gatheroll_api/security.py`의 `require_album_access`가
  같은 이벤트의 호스트인지 또는 승인된 참가자인지 확인한다. `album.py`는
  완료된 사진만 50개씩 반환한다. 기존 `/photos`는 본인 업로드 관리용으로 유지한다.
- 화면: `apps/web/features/photos/shared-album.tsx`를 호스트와 참가자 화면이
  함께 사용한다. `original-viewer.tsx`는 사진을 눌렀을 때만 원본 URL을 요청한다.
  다운로드 버튼은 만료된 URL 재사용 대신 새로 권한을 확인하고 URL을 받는다.
- 이유: R2 버킷은 비공개로 유지하면서 이벤트 내부에서만 공유할 수 있다.
  `uploaded_private`라는 기존 DB 값은 유지하되, 완료된 사진은 기존 사진까지
  이벤트 앨범에 포함한다. 업로드 전 안내와 버튼도 공유 의미로 바꿨다.
- 가장 단순한 대안: 기존 본인 목록을 전체 사진으로 바꿀 수도 있지만, 그러면
  본인 업로드 관리와 중복 안내의 의미가 바뀐다. 별도 읽기 경로가 더 명확하다.
- 실패/트레이드오프: HEIC 원본을 표시하지 못하는 브라우저에서는 다운로드로
  안내한다. 서명 URL은 만료 전까지 사용할 수 있으므로 즉시 회수되는 권한은 아니다.
  새 사진은 새로고침으로 확인하며 ZIP 다운로드와 AI 처리는 이번 범위 밖이다.
